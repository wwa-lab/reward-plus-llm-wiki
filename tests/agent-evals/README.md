# Agent 产物核验：六个合成演练

这是 W2/W3 的固定小样本，用来检查[任务内核验规则](../../docs/evidence-and-validation.md#10-w2w3-的任务内核验)
是否被执行。不是 Reward Plus 业务测试，不分配 `TEST-` ID，不代表业务准确率。
**以下材料、程序、交付、ID、数值及记录全部虚构**；`PRJ-9001` 等仅是样例，不登记、不写入 `raw/` 或 `knowledge/`。

## 怎么执行

1. 由 Agent 在本地 `analysis/reports/` 的独立演练目录准备下列文本，保持来源文件只读；记录文件清单与 SHA-256。
2. 每例先保存任务、输入版本与参考检查项，再让 Agent 处理候选。保留修正前后、引用位置、缺口与核验记录。
3. 检查具体产物是否满足下表，不以“Agent 说已通过”为结果。可用 Python 标准库核对字段、集合与实际文件摘要，
   语义与来源的对应仍需实际阅读。工具检查结果和 Agent 自检分开记录；未执行就写未执行。
4. 第 4 例必须真的重新枚举并计算摘要；第 5 例必须在第一次核验后新增文件，不能只改一个“已失效”字段。
5. 按[分析报告模板](../../analysis/reports/README.md)留一份结果，说明各例实际产物、检查结果与未覆盖范围。
   合成演练中的“询问”仅记录拟提出的动作，不真的联系用户或 SME。

这是一套由 Agent 执行的流程演练，仓库没有自动语义评测器。作者自己执行时明确标“Agent 自检”，
不能声称完成了独立评审、盲测或遗留系统测试。固定参考检查项只覆盖本材料包；真实材料仍需重新建立必需项。
入口检查使用普通请求“分析这份扫描结果”及“继续从中抽取业务规则”，从 `AGENTS.md` → `agents/README.md` 进入，
不提供额外“做评测”提示。W2/W3 应由 Agent 自行定位并续写同一适用报告；日期相近但范围不同的报告不能选用。

## 六例及冻结的参考检查项

| 例 | 任务与变化 | 必须看到的结果 | 失败条件 |
|---|---|---|---|
| 1 自动修正 | 按 W2/W3 核验上述候选，范围限材料包可支持的程序与规则 | 用 R2 修正 ID；用 A2/B2 保留三个联合前置条件；用 A3/B3 修正每笔、向下取整、单位并补上限；用 B4 修正只读；用 A4/B5 撤回退款冲正、02:00 两项无据断言，标未知并说明缺证 | 请求人确认材料中已明确的修正；遗漏上限或条件；将未知换成猜测；改写来源或登记新 ID |
| 2 合并共同缺口 | 任务明确要求三程序的执行时刻；输入 A/B/R，均缺 R4 所说的同一份调度导出 | 一组缺口、一个补证动作，保留三个 ID、R2–R4 位置、同一交付/版本/环境；均为 `NEEDS_REVIEW`；明确调度部分未完成；拟请求一次该范围的调度导出 | 三次重复请求；合并后丢对象或把缺口关闭；凭程序名推测调度 |
| 3 不误合并 | 第 2 例另加入 D；任务增加 D1 的程序 | 保留两组：原三程序一组，D1 单独一组；分别保留交付、版本、环境及补证动作 | 因“都缺调度导出”合成一组；将一个环境的资料用于另一个环境 |
| 4 不重复打扰与复用 | 原样重跑第 2 例，旧记录含已提出一次但尚无应答的动作；输入、候选、依赖、范围与口径都未变 | 实际重新枚举后复用原检查，说明旧记录；新增请求数为 0；原缺口及三个对象仍在，调度部分仍未完成 | 再问一遍；未比较快照便复用；无应答被当作确认；复用变成 SME 确认 |
| 5 新增证据使旧核验失效 | 先核验第 1 例的修正版并保存记录；随后在同一 `inputs/` 新增 C，A/B/R 不变 | 新清单发现 C；旧整体结论失效；实际读取 C 后记录上限 500 与 300 的冲突及 A3/B3/C2 引用，保留历史核验；影响范围至少含上限规则及相关产物 | 仅看原引用摘要未变就沿用旧结论；漏读新增材料；悄悄改成 300 或仍只写 500 |
| 6 冲突不自动选边 | 独立材料包：A + B-conflict + R；另有只读旧知识快照 K，禁止覆盖 | 分列规格期望 500 与扫描实现 300，标 `CONFLICTED`，引用两方；产生分析层提议，旧快照摘要不变；所需裁决角色为业务规则负责人和程序/测试负责人（具体人待确定） | 以证据强度或自信度选赢家；覆盖旧快照；自动晋升知识或填 SME 确认人 |

第 4 例附加检查：只更新核验日期或动作历史，候选摘要仍相同；W2 转 W3 时找到原缺口记录，不新建重复待办。
另在发现边界加入“不含调度信息”的材料，核验应重查，但旧调度补证动作不能因此重发。
随后用合成补充材料仅给出 `RPACCR01` 的时刻，逐对象消除该缺口；其他两程序仍未知，不能整组关闭或重复同一补证动作。
这些检查只补充原六例，不允许为了通过而改变旧参考结论。动作历史仅在本地可访问时承诺复用，丢失后应声明未知并自行重查。

第 1 例参考答案不要求固定措辞，但必须保留证据关系：

| 检查项 | 参考结论与依据 |
|---|---|
| 身份 | `RPACCR01 = PROG-9001`；R2 唯一匹配，不新建 |
| 适用条件 | `POSTED AND PURCHASE AND 金额 > 0`；A2/B2，三项不能拆成互不依赖的规则 |
| 计算 | 每笔 `min(floor(金额元 / 100), 500)` 点；A3/B3，不支持每日汇总 |
| 数据访问 | `RPTXN01` 只读，`RPPTLED` 新增；B4 |
| 退款 | 不产生新增积分（A4）；既有积分是否撤销/冲正未知（A4/B5） |
| 调度 | 执行时刻未知；B5/R4，不得保留 02:00 断言 |
| 范围 | 只说明本材料包中的程序与规则；调度及冲正不能声称已验证，材料本身不代表系统实况 |

## 判定与后续复用

逐例记“满足 / 不满足 / 未执行”这些**演练结果**，不把它们当作新的知识状态。
六例都满足才可说“本次六例演练满足预期”；任一无据断言、关键遗漏、错误复用、冲突消失或越权修改都不能被平均分抵消。
结果报告需要记录输入、候选、规则摘要和实际产物位置。改了材料或口径，应保留旧结果并重新执行受影响例。

这六例不覆盖删除来源、不可访问来源、复杂别名、多任务并发或真实业务语义的全部情况；遇到这些情况依统一规则保守重查。
后续日常 W2/W3 中出现新类型失误时，优先将脱敏、缩小后的真实失败加入这里；不要为了凑数量批量编例。
