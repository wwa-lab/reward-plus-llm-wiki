# agents/workflows/ — 工作流定义（规划中）

## 现状

**这里没有可执行的工作流。** 没有编排引擎、没有脚本、没有触发机制。

当前所有流程都是**手动**的：人把材料放进 `raw/PRJ-####/<类型>/`，复制 [README 里的提示词](../../README.md#79-可直接复制的-agent-提示词) 给 Cursor Agent，按文档里的步骤走。

分步流程写在 [docs/workflows.md](../../docs/workflows.md)（W0–W10，含每步的门禁）。本目录将来放的是那些流程的**机器可读版本**。

## 将来这里放什么

当某个流程被手动跑过若干次、稳定下来了，才可以写成本目录下的定义文件：

```markdown
# WF-00X：<流程名>

- 触发时机：
- 输入：
- 输出：
- 步骤：
  1. …
- 门禁（不满足则停止）：
- 允许的状态转换：
- 需要人工介入的点：
```

## 三条约束

1. **流程定义只描述"怎么做"，不含业务内容。** 程序名、规则、接口名属于 `knowledge/`，不写进这里。
2. **定义不覆盖 [AGENTS.md](../../AGENTS.md) 与 [agents/README.md](../README.md)。** 三者冲突时以 AGENTS.md 为准，修正定义。
3. **没被手动跑过的流程，不要写定义。** 把没验证过的流程自动化，只是把错误自动化。

## 候选流程（等手动跑顺了再考虑）

| 流程 | 说明 | 对应文档 |
|---|---|---|
| WF-001 导入材料 | 合规检查 → 定 `PRJ-` → 归档 `raw/PRJ-####/<类型>/` → 登记 `SRC-` | docs/workflows.md W1 |
| WF-002 扫描结果分析 | 程序清单/调用关系/数据访问/规则候选 | W2 |
| WF-003 规则抽取 | 单条规则拆分与登记 | W3 |
| WF-004 功能描述 | 业务语言的功能页 | W4 |
| WF-005 菜单映射 | 菜单 → 功能/程序，含置信度 | W5 |
| WF-006 批量作业梳理 | 调度、顺序、依赖 | W6 |
| WF-007 接口与外部系统梳理 | 边界判定 → `SYS-` / `IF-` 登记 → 字段映射 | W7 |
| WF-008 测试与验证 | 规格 → 执行 → 结果关联 | W8 |
| WF-009 影响分析 | 依赖追踪 + 缺口报告 + 功能 × project 矩阵 | W9 |
| WF-010 评审与晋升 | 人工评审 → 状态推进 | W10 |

**不要为了凑数提前写。** 一条被真实跑过三次的流程定义，价值远高于十条凭空写的。

**注意：`PRJ-` 目前不是独立的一步流程**，它折在 W1（定归属）和 W9（改动范围）里。等按 project 导入真的跑过几轮、
"定归属"这件事反复出现摩擦点，再考虑把它拆成独立流程——现在拆就是凭空设计。
