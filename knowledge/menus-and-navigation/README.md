# knowledge/menus-and-navigation/ — 菜单与导航

把用户看到的入口，连到后端的功能和程序。这是理解"用户怎么走到这段代码"的唯一途径。

## 放什么

`MENU-####-<slug>.md`，从 [templates/menu-entry-template.md](../../templates/menu-entry-template.md) 复制。

一页菜单项要讲清：

* 菜单名称与菜单路径（层级）
* 条目标签
* 导航目标
* 业务用途
* 关联的功能（`FUNC-####`）
* 关联的程序（`PROG-####`）
* 证据来源（菜单导出路径 + 位置）
* **映射置信度**
* 状态与待解问题

## 三条重要提醒

1. **菜单项与程序不是一对一。**
   * 一个菜单项可能触发一串程序；
   * 一个程序可能被多个菜单项调用；
   * 有的菜单项只是导航容器，背后没有业务处理；
   * 有的程序没有任何菜单入口（只被批量作业或接口调用）。

2. **映射必须有证据。** 依据可以是：调用链、程序名与菜单标签的对应、屏幕定义、SME 说明。没有依据就标 `INFERRED` 或 `NEEDS_REVIEW`，并在待解问题里写明"需要什么证据才能确定"。

3. **映射置信度单独记一列**（`mapping_confidence`：high / medium / low / unknown），与整页状态分开。菜单结构本身可以有证据（`EVIDENCE_FOUND`），但映射到功能是推断（`INFERRED`）——两者不冲突，写清楚即可。

## 不放什么

* 臆测的映射（→ `analysis/reports/`）
* 菜单导出的原始内容（→ `raw/PRJ-####/fe-menus/`）

## 有价值的缺口输出

**"未匹配菜单项"清单**是本目录最有价值的产物之一：哪些菜单找不到对应功能/程序，直接告诉你知识覆盖的盲区。这份清单放 `analysis/reports/`，并在本目录 README 的更新中引用。
