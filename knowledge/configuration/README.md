# knowledge/configuration/ — 控制参数

**能改变系统行为的可调配置**，一个控制文件（或数据区 / 一组硬编码常量）一页，ID 前缀 `CFG-####`。

控制文件是业务规则的**隐形载体**：代码里写 `IF STATUS = 'A'`，`'A'` 的真正语义在参数文件里。
这是遗留迁移最容易出事的一块——代码搬过去了、参数没搬或搬错，行为静默改变。

## 放什么

* 参数文件、数据区（`*DTAARA`）、用户空间（`*USRSPC`）、作业描述、系统值
* **硬编码在 CL / RPG 里的配置常量**（最容易漏的一类）
* 每个控制参数的：作用、参数项、取值域、读取方式、**反向映射（改它影响谁）**、迁移影响

## 不放什么

* **生产环境的具体值** → `raw/PRJ-####/control-files/`（敏感，很可能不得提交）
* 物理结构与字段类型 → `data-and-interfaces/`（`DATA-####`）+ `raw/PRJ-####/data-dictionary/`
* 由业务定期维护的业务数据表（如费率表）→ 按 `DATA-####` 处理
* 业务规则的条件与后果 → `business-rules/`（`RULE-####`）

## 与相邻层的分工

| 问题 | 落在哪 |
|---|---|
| 这个控制文件控制什么行为？参数有哪些？ | 本目录（`CFG-####`） |
| 改这个参数会影响哪些程序 / 规则？ | 本页的"反向映射"段 |
| 这个文件的物理结构和字段类型？ | `data-and-interfaces/`（`DATA-####`） |
| 生产环境当时的值是什么？ | `raw/PRJ-####/control-files/`（敏感，按环境 + 日期快照） |
| 参数取值触发了什么业务后果？ | `business-rules/`（`RULE-####`） |

## 命名

```text
CFG-0001-<控制文件slug>.md
```

（以上仅为命名**格式**示例，不是真实记录。请勿使用臆造的文件名或参数名。）

## 关键要求

1. **先判定真配置还是业务数据表。** 判据是"谁在改它、多久改一次"。判不准标 `NEEDS_REVIEW`。
2. **不记生产值。** 只记参数项、取值域与设计默认值。实际值属敏感信息。
3. **反向映射必须有。** 没有"改它影响谁"，本页对迁移的价值就少了一半。
4. **硬编码的配置也要登记。** 它们不在文件里，所以最容易被漏。
5. **各环境差异只记"是否存在"**，不记差异内容。
6. **列出涉及项目（`PRJ-####`）。** 参数是逐年叠加的产物——不知道某个参数是哪次交付加的、为什么加，就不敢删它。
