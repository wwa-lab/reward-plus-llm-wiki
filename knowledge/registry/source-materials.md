# 登记表：来源材料（SRC）

**当前最大 ID：0**（尚未分配任何 ID）

记录每一批材料——**进了 `raw/` 的，和留在 LAN 上的**。来源材料**不建独立知识页**，只在此登记一行 + 指向材料位置，避免与 `raw/` 重复。

**本表是材料位置的权威索引**：`SRC-####` ↔ LAN 路径 ↔ 所属 `PRJ-####`。
**材料没进库时，这份登记就是唯一的线索**——不登记就等于这批材料不存在。

| — | — | — | — | — | — | — | — | — | — | — |

（暂无记录。上表首行仅为占位，正式登记时替换。）

**「所属项目」填 `PRJ-####`；跨 project 或全局的填 `_shared`。** 这一列决定了这批材料归哪次交付，
也是迁移分批的边界依据——**不确定就写"待判定"，不要随便挑一个 project 塞进去**。

## 如何追加一行

1. **先定 project**：查 [projects.md](projects.md)，有对应 `PRJ-####` 就用；没有就先在那里登记一行。
2. 材料放进 `raw/PRJ-####/<类型>/`（跨 project 的放 `raw/_shared/<类型>/`）后，在本表登记一行。
3. 新 ID = 当前最大 ID + 1，例如 `SRC-0001`。
4. 类型：代码扫描结果 / 前端菜单 / 业务文档 / 测试用例 / 测试结果 / 图表图像 / 数据字典 / 配置快照。
5. 路径：进库的填 `raw/PRJ-####/<类型>/<文件>`；**没进库的填 LAN 位置，并在备注里写"未进库 + 原因"**。
6. **版本 / 日期、提供方、范围：知道多少填多少，不知道写"未知"，不要猜。**
7. **更新文件头部的"当前最大 ID"**。

## 状态取值

`EVIDENCE_FOUND` · `INFERRED` · `NEEDS_REVIEW` · `SME_CONFIRMED`（需记录确认人与日期）· `CONFLICTED` · `SUPERSEDED`

材料已进库、来源清楚 → `EVIDENCE_FOUND`。材料只登记未进库、来源不明或授权待确认 → `NEEDS_REVIEW`，
并在备注里写明"缺什么才能确认"。

## 敏感材料

若材料含源码片段、凭证、個人资料或生產数据：

* **不要提交**到 Git，保持未跟踪；
* 在本表备注列写明"含受限内容，待评审"；
* 在评审结论出来前**不得引用**它作为任何结论的证据。

`raw/*/control-files/`（配置快照）在 `.gitignore` 里默认忽略——与本表"敏感材料默认不提交"的约定一致。

## 已知限制一定要写

例如："仅覆盖 XXXLIB，不含 CL 程序"、"扫描时间为 2026-09，之后可能已变更"。
这条信息决定了基于它的所有结论的适用范围，省略它会导致后续误用。
