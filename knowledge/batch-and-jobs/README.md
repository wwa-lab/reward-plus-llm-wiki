# knowledge/batch-and-jobs/ — 批量作业与调度

作业流层面的知识：什么时候跑、按什么顺序跑、依赖什么、影响什么。

## 与 `programs/` 的分工

| 本目录 | `programs/` |
|---|---|
| 作业流、调度、顺序、依赖 | 单个程序的实现 |
| ID：`JOB-####` | ID：`PROG-####` |

**批量程序仍然是 `PROG-####`**，本目录描述的是"作业"这一层：哪些程序被串起来、什么时间、什么前置条件。

## 放什么

`JOB-####-<slug>.md`，从 [templates/batch-job-template.md](../../templates/batch-job-template.md) 复制。

一页作业要讲清：

* 作业名称与标识
* 调度周期与触发方式
* 前置依赖（作业、文件到达、时间窗口）
* 执行顺序与内部步骤
* 输入输出
* 下游影响（生成什么、喂给谁）
* 失败处理与重跑方式
* 相关功能、程序、数据、接口

## 规则

1. **依赖关系分两栏写**：有直接证据的 / 推断出来的。不要混在一起让人分不清哪些可靠。
2. 作业顺序错误会在迁移后造成严重事故，所以顺序与依赖必须有证据（作业调度清单、CL 程序、运行日志）。
3. 记录**时间窗口与数据量前提**——很多批处理行为依赖"日切前/后"这类前提。
4. 失败处理（重跑、断点续跑、人工干预）是迁移时最容易漏的部分，务必记录。

## 不放什么

* 单程序的实现细节（→ `programs/`）
* 调度系统的运维手册（不属于知识范围）
