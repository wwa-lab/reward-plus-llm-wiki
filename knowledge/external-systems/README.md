# knowledge/external-systems/ — 外部系统

Reward Plus **之外**的对端系统档案，一个系统一页，ID 前缀 `SYS-####`。

## 放什么

* 与我们有数据交换的外部系统：核心银行、卡组织、授权系统、总账系统、渠道、第三方服务。
* 每个系统的：业务职责、交互方式与协议、接口清单、交换的数据实体、SLA、安全授权、迁移影响。

## 不放什么

* **凭证、连接串、账号、生产地址与端口** —— 一律不进本仓库。
* 我们自己的程序与功能（→ `programs/`、`functions/`）。
* 单个接口的细节（→ `data-and-interfaces/` 的 `IF-####` 页）。
* 系统间的整体集成图与架构描述（→ `architecture/`）。

## 与相邻目录的分工

| 问题 | 落在哪 |
|---|---|
| 有哪些对端系统？ | 本目录 + [registry/systems.md](../registry/systems.md) |
| 某个系统负责什么、怎么连？ | 本目录的 `SYS-####` 页 |
| 我们跟它之间有哪些接口？ | 本目录的接口清单 + `data-and-interfaces/` 的 `IF-####` 页 |
| 接口传什么字段？ | `IF-####` 页，字段指回 `DATA-####` |
| 系统间的整体集成关系长什么样？ | `architecture/` |

## 关系维护

* `SYS-####` 页列出关联的 `IF-####`。
* `IF-####` 页的"对端系统"字段引用 `SYS-####`（**写 ID，不写系统名**）。
* 双向维护：系统页列接口，接口页指系统。

## 命名

```text
SYS-0001-<系统slug>.md
```

（以上仅为命名**格式**示例，不是真实记录。请勿使用臆造的系统名。）

## 注意

* 对端系统的名称可能是**商业敏感信息**。若公司政策不允许，用代号（如"渠道系统 A"）并注明原因。
* 系统档案的结论若来自业务文档或概念图，标 `INFERRED`；只有对端确认或代码证据支持时才标 `EVIDENCE_FOUND`。
