# 类型：测试执行结果

存放**执行证据**：运行日志、输出清单、截图、新旧系统对比报告。

这是证据强度最高的一类材料（系统实际跑出来的行为），也是唯一能支撑"已验证"结论的来源。

## 放什么

* 遗留系统上的执行输出与日志
* 新系统（Java）上的执行输出
* 新旧系统行为对比报告
* 执行截图、差异清单

## 不放什么

* 测试定义（→ 同 project 的 `test-cases/`）
* 对结果的解释（→ `analysis/reports/`）
* 含真实卡号、個人资料、生產数据的原始输出（先脱敏，无法脱敏则不入库）

## 使用方式

1. 存进来时登记 `SRC-####`，记录执行环境、日期、版本。
2. 在对应的 `TEST-####` 页面里引用：`raw/PRJ-####/test-results/<文件>，行 N`。
3. **没有引用就不能写"通过"。** 无证据的"通过"等同于编造。
4. 失败或意外结果 → 记为发现，可能推翻已确认知识；上报，不要改期望值让它变绿。
5. 引用格式：`raw/PRJ-####/test-results/<文件>，行 N` 或 `，第 N 页`（截图类）。

## 重要提醒

* 记录**执行环境**（哪个库、哪个版本、哪套数据、什么时间）。行为可能随环境变化。
* 新旧对比要写明两侧的版本与数据前提，否则对比结论不可复现。
* 一次执行只证明该次输入下的行为。要作为规则证据，需要覆盖边界值。
