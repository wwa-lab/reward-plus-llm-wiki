# 类型：原始测试用例

存放**测试定义**：用例集、测试脚本、测试清单、验收标准材料。

**执行结果放同 project 下的 `test-results/`，不要混在这里。**

## 放什么

* 业务或 QA 提供的测试用例集（Excel / CSV / 文档）
* 测试脚本、测试数据定义
* 验收标准、回归测试清单

## 不放什么

* 执行结果、日志、对比报告（→ 同 project 的 `test-results/`）
* 从用例里抽出来的结论（→ `analysis/`）
* **真实卡号、真实客户信息**（一律合成或掩码数据）

## 使用方式

1. 存进来时登记 `SRC-####`。
2. 抽取：业务场景、前置条件、输入、步骤、预期结果。
3. 派生出可复用的验证规格 → `TEST-####`，写在 `tests/validation/`。
4. 关联到 `FUNC-` / `PROG-` / `RULE-`。
5. 标出缺口：哪些规则没有任何用例覆盖、哪些预期结果与文档/代码不一致。
6. 引用格式：`raw/PRJ-####/test-cases/<文件>，工作表 X，第 N 行`（或用例编号）。

## 重要提醒

* **测试通过 ≠ 行为正确。** 通过只说明"该输入下是该输出"，不代表业务需求被正确实现。
* 原始用例可以原样保留在 `raw/`；`tests/validation/` 里放的是**规范化后可复用**的规格，两者用 ID 和路径互相关联，不复制全文。
* 用例里若含生产数据，先脱敏再入库；无法脱敏就不要提交。
