# 类型：代码扫描输出

存放**经批准**的遗留系统代码扫描结果。这是理解实际实现行为的主要证据来源。

## 放什么

* 程序清单与程序级元数据（名称、类型、语言、所属库、行数等）
* 调用关系（callers / callees）
* 数据访问摘要（读/写哪些文件、表）
* SQL 与数据访问汇总
* 业务规则抽取结果
* 依赖报告、静态分析输出

## 不放什么

* **完整源码**。本仓库不是源码仓库，源码留在它原本被批准的位置。
* 未经批准的扫描输出。
* 含凭证、连接串、個人资料、生產数据的输出。

## 提交前的检查

扫描结果里如果包含以下内容，**不要自动提交**，标记待评审并上报：

- [ ] 拷贝的源代码片段（超出"引用位置"范围）
- [ ] 凭证、令牌、连接串
- [ ] 個人资料或生產数据
- [ ] 超出批准范围的材料

## 使用方式

1. 存进来时登记 `SRC-####`（见 `knowledge/registry/source-materials.md`）。
2. 分析先落在 `analysis/reports/`，输出程序清单、调用关系、数据访问、规则候选。
3. 与已有 `PROG-` / `FUNC-` 对照：新增 / 一致 / 冲突 / 缺失映射。
4. 评审后才更新 `knowledge/programs/`。
5. 引用格式：`raw/PRJ-####/code-scan-results/<文件>，行 N`（跨 project 的材料用 `raw/_shared/code-scan-results/...`）。

## 注意

* 扫描输出只反映**扫描那一刻**的系统状态，且只覆盖被扫描的范围。引用时写明扫描日期与范围。
* 扫描结果说"程序 A 调用程序 B"，不等于"业务上 A 属于功能 X"。调用关系是事实，功能归属是推断。
* 不同批次的扫描结果可能口径不一致 → 记 `CONFLICTED`，不要挑一个当真理。
