# 类型：业务文档

存放业务侧提供的文档：PPT、PDF、Excel、Word、Visio 导出等。用途是理解**业务意图与期望行为**。

## 放什么

* 业务需求、功能说明、产品规格
* 业务流程图、操作手册
* 项目汇报材料（含业务范围的）
* 监管或合规要求文档（如允许存放）

## 不放什么

* 未经批准的内部文档
* 含個人资料、生產数据、凭证的材料
* 文档的分析结论（放 `analysis/` 或 `knowledge/`）

## 使用方式

1. 存进来时登记 `SRC-####`，记录版本与日期。
2. 让 Agent 输出：文档结构、涉及业务范围、功能、规则、接口，以及**文档没说清楚**的问题。
3. 初步结论放 `analysis/reports/`，区分"文档原文"与"Agent 推断"。
4. 与已有 ID 对照：是新增实体，还是已有实体的别名？
5. 评审后才创建 / 更新知识页。
6. 引用格式：`raw/PRJ-####/business-documents/<文件>，第 N 页`（或章节、工作表）。

## 重要提醒

* **文档描述的是期望行为，未必是已实现行为。** 与代码证据冲突时标 `CONFLICTED`，两边都留。
* **版本很关键。** 旧版文档和现行系统的差异本身就是重要发现，要写进冲突说明。
* 文档里的业务术语通常是**别名**的第一来源，记得同步进登记表。
* 不要因为文档写了就认定系统这么做；也不要因为代码没实现就认定文档错了——两者差异要交给 SME 裁决。
