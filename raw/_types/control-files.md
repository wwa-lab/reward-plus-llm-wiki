# 类型：配置快照

存放控制参数 / 配置文件在**某个环境、某个时点**的实际值导出。

## 为什么单列一个目录

配置的**实际值**和配置的**语义**是两回事：

* **语义**（这个参数是什么、干什么、取值域）→ `knowledge/configuration/`（`CFG-####`）
* **实际值**（生产环境当前配置成什么）→ 本目录

值随环境变化、随时间变化，且**往往是敏感的**（含开关、阈值、费率、有时含账号与连接信息）。
所以它按原始材料对待，不进知识层。

## 放什么

* 各环境的配置导出（参数文件、数据区、用户空间、作业描述）
* 硬编码常量的清单（从代码里抽出来的）
* 环境之间的差异对照（若公司允许保存）

## 不放什么

* 参数的业务语义解释（→ `knowledge/configuration/`）
* 任何**未获批准**的生产配置

## 命名与快照规则

**必须按环境 + 日期分开存放**，否则无法回答"生产当时是什么值"：

```text
<系统>-<控制文件>-<环境>-YYYY-MM-DD.csv
```

例如 `points-params-prod-2026-10-01.csv`。**不要覆盖旧快照。**

## 敏感性与提交

**这个目录的内容默认视为敏感。** 提交前必须确认：

1. 是否含凭证、连接串、账号、密钥？**含则不得提交。**
2. 是否含商业敏感值（费率、限额、风控阈值）？**按公司政策处理。**
3. 是否已获审批？

**含敏感内容时：保持未跟踪（不要 `git add`），登记 `SRC-####` 并标"待评审"，在结论出来前不得作为证据引用。**

`.gitignore` 里对 `raw/*/control-files/` 做了**默认忽略**，与本页"默认不提交"的约定一致。
要提交一份**已评审、已脱敏**的快照，用 `git add -f <路径>` 显式加入，并在 commit message 里写明评审人和脱敏范围。

`.gitignore` 不是安全控制——已经 `git add` 的文件它挡不住，被忽略的文件也不会出现在 `git status` 里。
详见 [../README.md](../README.md)。

## 登记与引用

1. 每批快照在 `knowledge/registry/source-materials.md` 登记一行 `SRC-####`。
2. `knowledge/configuration/` 的 `CFG-####` 页通过"证据与来源引用"段指向本目录。
3. **知识页只引用，不复制值。**
