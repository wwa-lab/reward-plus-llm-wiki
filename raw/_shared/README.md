# raw/_shared/ — 跨 project 的材料

存放**不属于某一个 project** 的材料。

## 什么材料会放这里

* 全量扫描输出（覆盖整个系统，不属于某次 feature 交付）
* 通用业务文档（术语表、总体业务说明、监管要求）
* 平台级配置（不属于某个 project 的参数）
* 跨多个 project 的对比报告

## 结构

按**材料类型**分子目录，**只建用到的**：

```text
_shared/
├── README.md
├── code-scan-results/
├── business-documents/
└── <其他类型>
```

类型规则见 [`../_types/`](../_types/)。

## 判断标准

**先问：这份材料是不是某一次 feature 交付带来的？**

| 答案 | 去处 |
|---|---|
| 是，属于某个 project | `raw/PRJ-####/<类型>/` |
| 不是，是全局或跨项目的 | 本目录 `<类型>/` |
| 不确定 | 放本目录，并在 `_MANIFEST.md` 里写明"归属待定" |

**不要因为"不知道属于哪个 project"就随便塞进一个 project。** 归属错了比不归属更糟——
它会让迁移批次的范围判断出错。

## 登记

与本目录其他材料一样：登记 `SRC-####`，`_MANIFEST.md` 写清来源与范围。
